Legacy profile configs rejected · --profile is now primary

v0.134.0 · May 26

--profile becomes the primary profile selector across CLI, TUI, and sandbox flows. Legacy profile configs (the v1 shape) are now hard-rejected with migration guidance. New on top: rollout-backed conversation history search (case-insensitive), per-server env targeting for MCP, OAuth on streamable HTTP MCP servers, parallel calls for MCP tools that declare readOnlyHint, and best-effort compaction of oversized connector tool schemas.

If you still ship a legacy profile block in config.toml, the CLI now refuses to start until migrated. Read-only MCP parallelism is a quiet perf win for tools that opted into the hint.

# new: explicit --profile selector + per-profile files
codex --profile work

[permissions]
network = "deny"
