claude-code

Source · code.claude.com/docs/en/changelog

Dynamic-workflow trigger renamed workflow → ultracode · acceptEdits prompts before exec-granting config writes

v2.1.160 · Jun 2

The dynamic-workflow trigger keyword changed from workflow to ultracode — the literal word workflow no longer starts a run (asking in your own words still works). acceptEdits mode now prompts before writing shell startup files (.zshenv, .bash_login) and build-tool configs that can execute code (.npmrc, .yarnrc, bunfig.toml, .bazelrc, .pre-commit-config.yaml, .devcontainer/). CLAUDE_CODE_OPUS_4_6_FAST_MODE_OVERRIDE is now a no-op.

If any script, alias, or onboarding doc tells people to type "workflow" to fan out agents, it silently stops triggering — rename to ultracode. The new acceptEdits prompts mean previously-unattended runs may now pause on config writes.

WebFetch rules now override preapproved domains · sub-1s MCP timeouts no longer abort every call

v2.1.162 · Jun 3

Explicit WebFetch(domain:...) deny/ask/allow rules now take precedence over the built-in preapproved-host auto-allow. MCP per-server timeout values below 1000 ms were being floored to a 1-second watchdog that aborted every tool call; sub-1000 ms values are now ignored (falling back to MCP_TOOL_TIMEOUT or the default). claude agents --json also gains a waitingFor field showing what a blocked session is waiting on.

If you leaned on the preapproved-domain auto-allow while also carrying an explicit WebFetch rule, the explicit rule now wins — re-check your allowlist. Any MCP server pinned to a sub-second timeout was failing every call and now works.

Pin allowed versions with requiredMinimumVersion / requiredMaximumVersion · /plugin list

v2.1.163 · Jun 4

New managed settings requiredMinimumVersion and requiredMaximumVersion make Claude Code refuse to start outside the allowed range and point users to an approved version. Adds /plugin list with --enabled/--disabled filters. Stop and SubagentStop hooks can now return hookSpecificOutput.additionalContext to feed Claude context and keep the turn going without being flagged as a hook error. stdio MCP servers get the same CLAUDE_CODE_SESSION_ID as hooks on --resume.

Version pinning gives admins a reproducible CLI baseline across a team. The Stop-hook additionalContext path lets you nudge the model after a turn without faking an error.
json// managed-settings.json
{
  "requiredMinimumVersion": "2.1.163",
  "requiredMaximumVersion": "2.1.168"
}

fallbackModel setting · glob deny rules · relayed-message auth hardening

v2.1.166 · Jun 6

New fallbackModel setting configures up to three fallback models tried in order when the primary is overloaded or unavailable; --fallback-model now also applies to interactive sessions, and Claude Code retries a turn once on the fallback after an unexpected non-retryable API error. Deny rules accept glob patterns in the tool-name position ("*" denies all tools). Messages relayed via SendMessage from other sessions no longer carry user authority — receivers refuse relayed permission requests.

The fallback chain is a real resilience win for long unattended runs that previously died on a single overloaded-model error. The relayed-message change closes a cross-session privilege path worth knowing if you orchestrate multiple sessions.
json// settings.json
{
  "fallbackModel": ["claude-opus-4-8", "claude-sonnet-4-6", "claude-haiku-4-5"]
}

v0.3.160 · Jun 2

Hook callbacks were swallowing abort signals — aborting during a PostToolUse hook left the calling process hanging. It now ends the turn with a final result message.

If you wrap the SDK and cancel turns from hooks, you were at risk of a wedged process. One bump removes it.

Native builds default to embedded find/grep · refusals carry stop_reason: "refusal"

v0.3.162 · Jun 3

On native builds, Agent SDK sessions now default to fast embedded find/grep in Bash (matching the interactive CLI) instead of always registering the dedicated Grep/Glob tools. To keep the dedicated tools — e.g. to intercept searches via canUseTool or hooks — name them in the tools option or allowedTools. Separately, refusal errors now carry stop_reason: "refusal" and stop_details on the assistant message and in transcripts.

If your host inspects or gates Grep/Glob calls, they may simply stop firing until you opt the tools back in. The refusal metadata lets you detect refusals without brittle text-matching.
ts// keep dedicated search tools on native builds
query({ prompt, options: { allowedTools: ['Grep', 'Glob', /* ... */] } });

1

Re-check WebFetch permission rules after the 2.1.162 precedence change

Breaking risk

As of Claude Code 2.1.162, explicit WebFetch(domain:...) deny/ask/allow rules take precedence over the built-in preapproved-host auto-allow. If your config mixes an explicit WebFetch rule with reliance on the preapproved-domain allowlist, the explicit rule now wins and may block or prompt for hosts that previously sailed through.

Permission changes are silent until a fetch you expected to work starts asking — or one you meant to block stops being blocked. Audit before it surprises a run.
bashrg -F 'WebFetch(' .claude/settings.json .claude/settings.local.json
# reconcile explicit rules with the hosts you relied on auto-allowing

2

Opt Grep/Glob back in if your Agent SDK host intercepts searches

Breaking risk

Agent SDK v0.3.162 makes native builds default to embedded find/grep in Bash instead of registering the dedicated Grep/Glob tools. If you gate or observe searches via canUseTool or hooks, those interceptors stop firing until you name the tools explicitly.

Your search guardrails can go dark with no error — the searches just route through Bash instead. Naming the tools restores the hook surface.
tsquery({
  prompt,
  options: { allowedTools: ['Grep', 'Glob', /* your other tools */] },
});

3

Configure a fallbackModel chain for unattended runs

Reliability

Claude Code 2.1.166 adds a fallbackModel setting that tries up to three models in order when the primary is overloaded or unavailable, and retries a turn once on the fallback after an unexpected non-retryable API error. Set it anywhere you run long or unattended sessions.

A single overloaded-model error used to kill an overnight or CI run; a fallback chain turns that into a transparent retry.
json// settings.json
{
  "fallbackModel": ["claude-opus-4-8", "claude-sonnet-4-6", "claude-haiku-4-5"]
}

Tip

Agent SDK v0.3.162 surfaces refusals with stop_reason: "refusal" and stop_details on the assistant message and in transcripts. If you currently sniff refusals by string-matching the error content, switch to the structured field.
