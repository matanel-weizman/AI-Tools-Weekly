Adopt Codex permission-profile inheritance for multi-project workspaces

Security

Codex 0.133.0 added permission-profile inheritance and a managed requirements.toml. Define one base profile (network deny, fs scoped to project root) and have per-project profiles extend it instead of copy-pasting.

Single source of truth for tool permissions. New project = one short delta file, not a 50-line config you forgot to update.
toml# ~/.codex/profiles/base.toml
[permissions]
network = "deny"
fs_write = ["$WORKSPACE"]

# ./project/.codex/profile.toml
[profile]
extends = "base"

[permissions]
network = "allow"  # this project needs it

4

Route batch jobs through service_tier: "flex"

Cost

If your service has a batch path (overnight reports, bulk classification, async enrichment) that does not need interactive latency, pass service_tier: "flex" on Responses calls. The new SDK exposes it explicitly per call.

Flex pricing meaningfully undercuts the default tier for jobs that can tolerate slower turn-around. Easy lever, real money over a month.
tsasync function classifyBatch(items: string[]) {
  return Promise.all(items.map(input =>
    openai.responses.compact({
      model: "gpt-5",
      input,
      service_tier: "flex"  // accept latency, save cost
    })
  ));
}

Surface web-search citations using web_search_call.results

Trust

Including web_search_call.results in your Responses API call returns the raw sources the model consulted. Display them next to the model's answer so users can verify claims rather than trusting paraphrase.

Public assistants live or die on perceived trustworthiness. Showing sources is cheap to ship and shifts user perception fast.
tsconst r = await openai.responses.create({
  model: "gpt-5",
  input: query,
  tools: [{ type: "web_search" }],
  include: ["web_search_call.results"]
});

const sources = r.output
  .flatMap(o => o.type === "web_search_call" ? o.search_results : []);
// render sources alongside r.output_text in the UI
