Claude Sonnet 5 is the new default model (1M context)

2.1.197 · Jun 30

Claude Sonnet 5 becomes the default model in Claude Code, with a native 1M-token context window and promotional pricing of $2/$10 per million tokens through August 31. Update to 2.1.197 or newer to get access; existing model pins still work if you prefer to stay on your current model.

Default permission mode renamed to "Manual"; AskUserQuestion no longer auto-continues

2.1.200 · Jul 3

The "default" permission mode is now labelled "Manual" across the CLI, --help, VS Code, and JetBrains — --permission-mode manual and "defaultMode": "manual" are accepted alongside the old default. Separately, AskUserQuestion dialogs no longer auto-continue by default; you now opt into an idle timeout via /config. A startup crash when disabledMcpServers/enabledMcpServers is a non-array value was also fixed.

Unattended flows that relied on AskUserQuestion silently auto-continuing will now block waiting for input unless you configure an idle timeout.
bash# old and new spellings both work
claude --permission-mode default ...
claude --permission-mode manual  ...

New OTel event logs the model's response text on upgrade

2.1.193 · Jun 25

A claude_code.assistant_response OpenTelemetry log event now carries the model's response text. It is redacted unless OTEL_LOG_ASSISTANT_RESPONSES=1, but when that variable is unset it follows OTEL_LOG_USER_PROMPTS — so any deployment that already logs prompt content will start emitting response content the moment it upgrades. This release also adds autoMode.classifyAllShell to route every shell command through the auto-mode classifier.

If you ship telemetry to a shared backend, upgrading can silently start exporting full model responses — set OTEL_LOG_ASSISTANT_RESPONSES=0 before you roll out.
bash# keep telemetry to prompts-only after upgrading
export OTEL_LOG_ASSISTANT_RESPONSES=0

Subagents run in the background by default; Chrome GA; auto-PR on finish

2.1.198 · Jul 1

Subagents now run in the background by default, so the main session keeps working and is notified when they finish. Claude in Chrome reached general availability. Background agents launched from claude agents now commit, push, and open a draft PR when they finish code work in a worktree instead of stopping to ask, and the built-in Explore agent now inherits the session's model (capped at opus) rather than running on haiku.

Delegated work parallelises without babysitting, but background agents can now push branches and open PRs on their own — review your worktree and permission setup before running them unattended.

requestId on permission callbacks, blocked workflow events, masked credential injection

v0.3.199 · Jul 2

Permission callbacks now receive a requestId so you can correlate a decision back to the exact request that triggered it. Workflow agent events gain a blocked field, and sandboxed commands now support masked credential injection — secrets are made available to a command without appearing in logs or transcripts.

Correlating permission prompts by requestId removes the guesswork in multi-agent orchestrators, and masked injection lets sandboxed steps use secrets without leaking them.

  audit.log({ requestId, tool });
  return { behavior: 'allow', updatedInput: input };
}

Query.reinitialize() recovers a session after a transport gap

v0.3.195 · Jun 26

A new Query.reinitialize() method re-sends the initialize control request and redelivers any pending permission or dialog prompts after a transport gap. If your SDK host drops and reconnects its channel to the agent, you can now resync state instead of tearing the session down.

Long-lived SDK sessions behind flaky networks or load balancers can recover in place rather than losing an in-flight permission prompt.
typescriptsocket.on('reconnect', async () => {
  await query.reinitialize();
});

MCP servers can now be given per-server timeout options instead of one global value, and the SDK emits a runtime warning when a callback configuration is shadowed by another. A mapping bug where SDKUserMessage.isSynthetic was not carried through to isMeta on ingestion was also fixed.

A single slow MCP server no longer forces you to loosen the timeout for every server, and the shadowing warning surfaces config mistakes that used to fail silently.

Practical ideas — 5 ideas this week

Concrete ways to use this week's changes in your Node / TypeScript service · each tied to a changelog item above
1

Audit unattended flows for the Manual-mode + AskUserQuestion behavior change

behavior change

Claude Code 2.1.200 renamed the default permission mode to "Manual" and stopped AskUserQuestion dialogs from auto-continuing. Any CI job, cron, or headless script that assumed a question would eventually self-resolve will now hang. Configure an explicit idle timeout via /config, or restructure the flow so it never asks a question in unattended mode.

A silently-blocking prompt in an overnight pipeline looks identical to a hang — you find out when the job never finishes.
bash# both spellings accepted; be explicit in scripts
claude --permission-mode manual -p "..."

2

Pin OTEL_LOG_ASSISTANT_RESPONSES=0 before upgrading if you ship telemetry

privacy

The new claude_code.assistant_response OTel event follows OTEL_LOG_USER_PROMPTS when its own flag is unset. If your service already logs prompt content to a shared observability backend, upgrading will start exporting full model responses too. Set OTEL_LOG_ASSISTANT_RESPONSES=0 in the environment before rolling out the new version.

Model responses can contain code, secrets, and customer data — you do not want them landing in a telemetry pipeline by accident.
bash# in your deploy env / Dockerfile
ENV OTEL_LOG_ASSISTANT_RESPONSES=0

Upgrade Codex to 0.142.5 if you run it with tracing enabled

security

Codex 0.142.5 stops full Responses WebSocket request payloads from being written to trace logs. If any of your machines run Codex with verbose tracing on — CI runners, shared dev boxes — those logs may already contain complete request bodies. Upgrade, then rotate anything that may have been captured.

Trace files are routinely shipped to central logging, so a payload leak here can quietly widen the blast radius of a single request.

Correlate SDK permission decisions with requestId and use masked credential injection

SDK

If your service embeds the Claude Agent SDK, read the new requestId in your canUseTool callback and stamp it onto your audit log so every allow/deny ties back to a concrete request. For sandboxed steps that need a secret, switch to masked credential injection (SDK v0.3.199) so the value is available to the command but never rendered into logs or transcripts.

Auditable, per-request permission decisions and leak-proof secret handling are exactly what a security review of an agent integration will ask for.
typescriptcanUseTool: async (tool, input, { requestId }) => {
  auditLog.push({ requestId, tool, at: Date.now() });
  return { behavior: 'allow', updatedInput: input };
}
